Full skill instructions (SKILL.md)

Landing Page Roaster 🔥

Funny enough to share, useful enough to act on.

1. Get the page

  • Source code in the repo: read the hero, sections, CTAs, meta tags and images.
  • URL: fetch it if a web or browser tool is available. Screenshot: analyse it visually.
  • Ask (or infer) the target audience and the one action the page should drive.

2. Score (0–10 each, total out of 100)

AreaWhat to judge
5-second testCan a stranger say what it is, for whom, and why it's better?
HeadlineSpecific outcome vs vague buzzwords ("All-in-one platform for synergy")
CTAOne clear primary action, visible above the fold, action verb, low friction
Social proofReal logos, numbers, testimonials with faces/names, placed near CTAs
Clarity of offerFeatures → benefits; pricing transparency; objections answered (FAQ)
Visual hierarchyContrast, whitespace, scannability, consistent design
TrustSecurity, guarantees, contact info, privacy, polish (typos, broken links)
Speed & techHeavy images, layout shift, missing meta/OG tags, no favicon
MobileThumb-friendly CTA, readable text, no horizontal scroll
Story / flowProblem → solution → proof → action

3. Output

# 🔥 Roast: <site> — 62/100

**The roast (3–5 sharp lines):** witty, specific, never mean about people.
> "Your headline says 'Empower your workflow'. Every SaaS since 2012 says that. What do you actually DO?"

## ✅ Quick wins (< 30 min)

Rules

  • Roast the page, never the person. Every joke must point at a real, fixable issue.
  • Be specific: quote the actual copy and name the actual section.
  • Base the rewrites on what the product really does. Don't invent features or stats.
  • If the page source is in the repo, offer to apply the fixes directly in code.
